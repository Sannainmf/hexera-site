Six phases,
one pipeline.

Agents take each part from raw CAD to solver-ready: an interview up front, an explicit plan, hard quality gates, and an automatic retry when a gate fails.

  1. Intake

    01

    An AI meshing engineer interviews you: what the part is, internal or external flow, working fluid, units, which openings are inlets and outlets, near-wall resolution (y+ target). It proposes a mesh engine and asks before assuming, so ambiguity gets a question rather than a guess.

    • Purpose
    • Ports
    • y+ target
    • Engine

  2. Geometry

    02

    The CAD is read as exact math, not a picture: bounding box, solid count, watertightness, every opening measured for position and bore. Defects are named to your face (a gap, a non-manifold edge, a disconnected volume) before any compute is spent.

    • STEP
    • IGES
    • Measured, not guessed

  3. Plan

    03

    A planner turns your intent into numbers: base cell size from the bore, refinement levels per feature, prism layer count and first-layer thickness from your y+ target, all inside an explicit cell budget.

    • Cell budget
    • Refinement
    • Layers

  4. Mesh

    04

    The plan is authored into a native case and run on cloud compute, snappyHexMesh or gmsh, chosen for the job. Boundary layers, feature-edge snapping, port-local refinement.

    • snappyHexMesh
    • gmsh
    • Cloud run

  5. Gate & retry

    05

    Deterministic gates measure the result: non-orthogonality, skewness, port integrity, budget. A failing mesh is not delivered. It is diagnosed, the plan is revised, and the mesher runs again, automatically, up to three attempts.

    • Hard gates
    • Auto-retry
    • No silent failures

  6. Review & deliver

    06

    A reviewer agent inspects the passing mesh, both metrics and visuals, and only a PASS ships. You get the mesh with a quality scorecard, solver-ready for OpenFOAM or Fluent.

    • AI review
    • Scorecard
    • OpenFOAM
    • Fluent
